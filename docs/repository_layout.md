# Repository Layout

This document expands the repository map in `README.md` with artifact conventions and entry points.

## Top-Level Map

| Path | Purpose |
| --- | --- |
| `README.md` | Reader entry point: the study, the results at a glance (under test), the three reproduction tiers, data sources. |
| `CHANGELOG.md`, `CITATION.cff`, `LICENSE` | Versions of the artifact, how to cite it, and the MIT licence. |
| `docs/` | Reader-facing documentation, indexed in `docs/README.md`. |
| `docs/figures/` | The hand-made graphical abstract and the notes behind the generated figures. |
| `conf/` | Hydra configuration: provider profiles, sampling, embedding, experiment presets, and the campaign plans under `conf/rerun/` (`final.yaml` is the reported campaign). |
| `scripts/` | The pipeline and the reproduction interface; every script is indexed in `docs/reproduction.md`. |
| `prompts/` | Frozen task prompts (Task 1, Task 2, Task 3, the sensitivity and ablation variants). |
| `run_configs/` | Tracked example provider matrices for the JSON path. Local `current_run*.json` files are ignored. |
| `data/raw/` | The NICE CSV; other downloads stay local. |
| `data/processed/` | Reviewed seeds, benchmark items and probe items; the May 2026 metric snapshots under `archive/`. Raw run outputs are ignored and archived on Zenodo. |
| `outputs/` | The tracked results (paper tables, macro file, provenance, ablation summaries, probe summaries, figures) and the benchmark reviews; the explicit allow-list is in `.gitignore`. May 2026 summaries under `archive/`. |
| `tests/` | Unit, CLI, parsing, paper-export, benchmark-reproduction, link and reported-number checks. Shared fixtures live in `tests/helpers.py`. |
| `.github/workflows/` | CI: install via `uv` from the lockfile, whitespace check, ruff lint and format check, the unittest suite with a coverage report (no enforced threshold). |
| `.gitattributes` | Keeps the whitespace check away from generated tables. |
| `AGENTS.md` | AI-assistant tooling configuration. Not a research artifact. |
| `pyproject.toml`, `uv.lock` | Python project definition and lockfile. |

## Variant Suffix Convention

Several artifacts come in parallel variants. The suffix encodes the variant; the unsuffixed file is the default (NICE/PROMISE, `MUST`).

| Suffix | Meaning |
| --- | --- |
| _(no suffix)_ | NICE/PROMISE dataset, `MUST` mandatory variant — the **main** result path. |
| `_mlm_tapt` | `limsc/mlm-tapt-requirements` dataset, `MUST` variant — **co-primary** dataset. |
| `_shall` | NICE/PROMISE dataset, `SHALL` robustness variant. |
| `_mlm_tapt_shall` | `mlm_tapt` dataset, `SHALL` robustness variant. |
| `_pure` | PURE document-context ablation cell, `MUST` only (`docs/context_ablation.md`). Ablation-only; never pooled into headline numbers. |

Example: `outputs/benchmark_statements_review.csv` is the NICE/MUST review table; `outputs/benchmark_statements_review_mlm_tapt_shall.csv` is the `mlm_tapt`/SHALL review table.

## CSV + Markdown Pair Convention

Many curated artifacts under `outputs/` and `docs/final_seed_documents/` exist as a `.csv` and a sibling `.md` with the same stem. This is intentional: the CSV is the machine-readable evidence, and the Markdown is the human-readable rendering used during review. Both are tracked.

## Where to Look For

| You want to … | Go to … |
| --- | --- |
| See the full experimental setup (benchmark, prompts, request protocol, cohort, limitations) | `docs/experimental_setup.md` |
| Understand the study claim and evaluation design | `docs/evaluation.md` |
| See how every benchmark item was derived, step by step, with the exact templates | `docs/benchmark_ground_truth.md` (generated by `scripts/export_benchmark_ground_truth.py`) |
| Rebuild the benchmark from reviewed seeds | `scripts/prepare_benchmark.py`, `docs/reproduction.md` |
| Understand how headline numbers are aggregated | `docs/aggregation.md` |
| Reproduce the pipeline end-to-end | `docs/reproduction.md`, `scripts/reproduce.sh` |
| See how artifacts map to paper figures/tables | `docs/results_mapping.md` |
| Regenerate the manuscript's LaTeX number macros from the artifacts | `scripts/export_paper_numbers.py` (writes `numbers.tex`; see `docs/results_mapping.md`) |
| Understand pipeline code architecture | `docs/architecture.md` |
| Understand Git/artifact policy | `docs/repository_hygiene.md` |
| Common reviewer questions | `docs/faq.md` |
| Launch or resume the campaign with one command | `docs/experiment_runbook.md`, `scripts/rerun_all.py` |
